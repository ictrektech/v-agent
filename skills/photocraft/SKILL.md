# PhotoCraft

先调用 `photocraft_catalog` 读取当前服务实际提供的工具及参数，再用 `photocraft_call` 调用原生 MCP 工具。工具名和参数必须来自目录，不能猜测。工作区、文件权限和认证绑定当前 VOS 用户；不要索要 token。

遵循「探、改、验」：目录与参数查清后直接执行用户要求的编辑；查看工具返回的预览，核对位置、范围和是否伤到其他区域，再显式导出交付。简单编辑一次完成；同一处连续两次调整仍不满足要求，换方法或明确说明限制。保持同一个 MCP 会话，使连续调用操作同一份文档。打开另一张图片会改变活动文档。

只读写用户明确指定的图片和输出。工作区图片先用 `photocraft_import(file_path)` 导入并打开；它返回当前用户获准目录里的原生路径与文档信息。随后用 `photocraft_call` 连续编辑，最后用 `photocraft_export(output_file)` 导出回工作区，再交付该文件。输出父目录须已存在。

同一专家的原生文档会话跨工具调用保留，无需自行传会话 ID。原生目录查询可用 `vos_api` 的 `photocraft` 服务访问 `/volumes`、`/index`。文件上传使用专用导入工具，它按文件桥协议发送原始图片字节；无需猜测上传参数或改动目录权限。

用户提供的矩形坐标按其声明的单位和原始边界使用，不扩大范围，不凭空创造选区。局部处理应先建选区或蒙版，再执行调整，最后预览验证。不要把整图处理宣称为局部处理。

原生服务提供文档、命令、预览和导出工具，不提供桌面窗口控制或生成式修图。生成和补绘使用 V-Scheduler/Image Studio；PhotoCraft 用于像素、图层和选区编辑。服务不可用时明确报告，不能虚构编辑或产物。

实现参考 v-harness 0.1.12 的 PhotoCraft 用户能力代理，以及 PhotoCraft 的 `docs/vos-integration.md`；工具直接来自 PhotoCraft MCP，而非 v-harness 专用插件。

继续修改时导入上一轮导出的成品；返工则从出错步骤之前的版本开始。会话重启或空闲失效后，如出现 `no open document`，重新导入最近成品再继续，不假定历史文档仍在内存。

命令坐标按原生目录声明的单位处理：像素参数先读文档尺寸；只有明确声明为 0..1 的参数才使用比例。用户给出的框和笔迹保持原始范围。

最终回复展示 `photocraft_export` 返回的工作区文件，使用当前问题的语言简述结果；中间探测和重试细节只在失败影响交付时说明。
